## 修复：mid_autumn 活动 `__env=app` 无法进入 App 专属页
- 根因：`src/utils/env.js` 的 `isApp()` 只读 `window.location.search`，而活动页是 hash 路由，参数拼在 `#/` 之后（`/event/mid_autumn/#/?__env=app`），`location.search` 为空 → 判断恒为 false。
- 修复：`env.js` 新增 `getUrlParams()`，同时解析 search 与 hash 中的 query（参考 `src/pages/topic/index/components/Mobile.vue` 的写法）；新增 `syncAppEnv()` 把 url 上的 `__env` 同步/清除到 localStorage（显式传非 app 值时清除）。
- `src/pages/event/mid_autumn/index.js`：`applyAppEnv()` 前调用 `syncAppEnv()`。
- `src/pages/event/mid_autumn/router.js`：app 路由 `/` → `/index` 重定向改为函数式 `redirect: (to) => ({ path: "/index", query: to.query })`，避免跳转丢 query。
- 注意：全站约定 `__env=app` 也可通过 localStorage 持久化（其他活动页在入口 `isApp() && localStorage.setItem("__env","app")`），同域下会影响其它活动页的展示形态。

## Detail_App 活动介绍文章加载
- `intro_id` 取法与 `components/introduce.vue` 一致：`this.years.find((item) => item.year == this.year)?.intro_id || 0`。
- 在 Detail_App 里做成 computed `introId` + `watch introId { immediate: true }` 去调 `loadArticle(id)`。原因是 `years` 由 `mixins/years.js` 异步拉取，用 computed 才能在 years 到位后自动触发加载（原来在 onClickTab 里手写 `this.loadArticle(id)` 属于 id 未定义的 bug，已删除该分支）。
- 注意 Detail_App 同时 `inject: ["years"]` 与 mixin 的 `data.years`：Vue2 中 initInjections 早于 data，故 mixin 的 data.years 会覆盖注入值，实际用的是 mixin 自己拉的数据。

## Detail_App v-html 富文本字号限制
- 用户反馈 getArticle 返回的 HTML 用 v-html 插入后字体太大。
- 方案：在 `.m-content` 上设基准 `font-size: 3.6vw`，并对 `p/span/div/li/font` 用 `font-size: inherit !important` 压过文章自带行内样式（!important 是必须的，富文本常带 inline style）；`h1-h3` 4.2vw、`h4-h6` 3.8vw；`img` max-width:100% + height:auto 防溢出；`* { max-width:100% }` 兜底。用户自己调过 .m-content 的 padding（10vw 2vw 0 2vw），改动时保留。

## 项目头像兜底约定（全项目检索结论，Poem.vue 已按此改）
- 首选工具函数：`showAvatar(url, size)`（`@jx3box/jx3box-common/js/utils`，源码 node_modules 里 utils.js:35）。空值返回 jx3box 的 `default_avatar`；把 `http:` 修正为 `https:`（QQ 头像协议）；`size` 支持 `"s"/"m"/"l"` 或数字，拼 `?x-oss-process=style/avatar_x`。
- 用法参考：`src/views/Rank/Dps.vue:492` `showAvatar(item?.user_info?.user_avatar)`；`src/pages/event/jx3cxk/components/Item.vue:150` `showAvatar(avatar, 240)`；`src/views/Lover/Join.vue:91` el-image + showAvatar。
- 二次兜底写法（多字段兼容）：`src/components/rank/lover/v2/DestinyCardUseDialog.vue:161` `showAvatar(a?.avatar || a?.user_avatar || a?.avatar_url || "https://cdn.jx3box.com/image/common/avatar.png")`。
- 投票类活动（同为 vote_items）的数据层兜底：`src/pages/event/jx3cxk/Index.vue:247`、`src/pages/event/xuanfuleidong/Index.vue:151` → `if (!item?.user_info?.avatar) item.user_info.avatar = ${__cdn}image/common/avatar.png`。注意 vote 接口字段是 `user_info.avatar`，不是 `user_avatar`（Dps.vue 用的是用户接口的 user_avatar）。
- 组件化兜底：`@/components/event/avatar.vue`（el-avatar 包装 + `showAvatar(avatar, "l")`），jbsci/jx3dat 在用。
- 加载失败兜底：项目里用 `@error`（如 `src/views/Rank/Rank.vue:13` 用 `:onerror="defaultBossIcon"`）、替换 src 后 `onerror = null` 防循环。
- Poem.vue 采用组合方案：load 时 `showAvatar(info.avatar || info.user_avatar, "m")` 归一化（空值由公共函数返回官方默认头像）+ 模板 `@error="onAvatarError"` 兜底；`DEFAULT_AVATAR = showAvatar("")` 取公共库 default_avatar，不再自己拼 `__cdn`。
- 踩坑：`@error` 兜底「没生效」的真因是模板字段名拼错（`item.user_info?.aavatar`），src 恒为 undefined → 浏览器根本不发请求、不触发 error 事件。排查 img 兜底失效时先确认 src 是否真的有值。
- 公共库里相关函数只有 `showAvatar` / `resolveImagePath` / `getThumbnail`；`checkImageLoad(jq)` 依赖全局 jQuery（库内未 import），且只做 cdn→oss 域名切换，全项目零引用，不要用。
